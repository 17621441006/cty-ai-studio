# 尘路加载、取景与专注控件

- 进入尘路时下载的村庄、卡卡西模型与贴图由 36,900,189 字节降为 10,908,111 字节（减少 70.4%；不含原本很小的龙模型和应用代码）。这些资源仍然只在打开尘路后请求。
- 卡卡西改为二进制属性存储，省去 54 MB 数字 JSON 的解码与解析。原顶点、三角形、蒙皮权重、骨骼和服装均保留；贴图转为同尺寸 WebP。其他 Minecraft 场景继续使用原资源。
- 村庄只合并同材质、同平面的非贴图方块面。所有贴图建筑面逐字节保留，平面覆盖范围不变。顶点由 5,298,612 减至 2,502,148；地形编码减少至 6.13 MiB。原始资源没有删除。
- 贴图与地形并行下载，地形解码在可终止的 Worker 中进行。关闭窗口会取消请求、终止 Worker、释放几何与贴图。版本化模型与地形复用浏览器缓存。
- 镜头的水平朝向与龙的爬升切线分离。跟随/侧观保持俯视；龙背视角将视线约束在村庄内部，飞越山岩及外侧转弯时仍能看到景观。沿用经过地形检查的封闭飞行路径。
- 专注计时默认显示右上角小条。设置按需展开，开始或暂停后收起；计时器独立更新，不再每 250 ms 触发整个飞行组件重渲染。

## 验证

`node scripts/qa/dust-road.cjs` 验证卡卡西模型属性等价、全部村庄表面的覆盖范围、三个视角与四种屏幕比例下两圈飞行（7,692 个采样）的景观可见性、闭环连续性，以及计时设置的展开和收起。

`node scripts/qa/performance.cjs` 验证应用隐藏/恢复、帧时钟与音乐的隔离。

同时执行 TypeScript 检查和正式构建。当前环境没有可用的浏览器 QA，未声称真实 iPhone 的加载秒数、帧率或 Safari 实测结果。

离线资源可用 `python3 scripts/prepare-flight-assets.py` 从保留的原始资产重建（需要 Pillow；不参与网站运行时）。

本次主站修复同步到 `main` 与 `kimi-deploy`，不改变 Kimi 的独立构建配置。用户报告的 Kimi 发布白屏按本轮优先级留待后续单独排查。
